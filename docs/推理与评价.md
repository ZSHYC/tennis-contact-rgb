# 推理与评价

[返回 README](../README.md)

以下命令在仓库根目录及 `conda activate tennis-contact` 后执行。单视频推理直接使用视频路径；批量推理与评价使用 `prepare` 生成的数据清单。

## 单视频推理

```bash
tennis-contact predict \
  --video data/video/match.mp4 \
  --checkpoint weights/best.pt \
  --device cuda \
  --output runs/match.json
```

CPU 示例：

```bash
tennis-contact --threads 4 predict \
  --video data/video/match.mp4 \
  --checkpoint weights/best.pt \
  --device cpu \
  --output runs/match.json
```

`--threads` 是全局参数，放在子命令前。`--video` 与 `--dataset` 二选一；单视频推理不需要标注。

## JSON输出

| 字段 | 含义 |
| --- | --- |
| `model` | 模型名称 `TennisContactNet` |
| `video` | 输入视频路径 |
| `frame_times` | 每个原生帧的 PTS，单位秒 |
| `scores` | 每帧两个分数，列顺序固定为 `[hit, bounce]` |
| `events` | 阈值、峰值与 NMS 处理后的事件列表 |
| `thresholds` | 本次事件解码使用的 hit / bounce 阈值 |
| `cost` | 读取、前向、时间轴还原耗时和显存等统计 |
| `sample_id` | 数据清单中的视频ID，仅批量模式写入 |

每条事件包含 `frame_number`、`event_type`、`score` 和 `time_seconds`。帧号从0开始，时间相对视频第一帧；`frame_times` 保留视频自身 PTS，可能不从0开始。

分数由事件强度与类别分配共同生成，取值在0到1之间。分数用于事件筛选，不代表已校准的物理接触概率。

输出是 JSON 文件；命令行同时打印运行成本。CPU运行时 `peak_allocated_bytes` 为0，CUDA运行时表示PyTorch峰值allocated显存。吞吐包含视频读取和模型计算，离线吞吐不表示在线延迟。

推理为每个视频只建立一次采样映射，保留视频解码器和有界 JPEG95 处理后帧缓存，并在计算当前窗口时预取下一个窗口。重复采样槽、上下文和 logits 平均规则不变；逐窗结果直接累加到原生时间轴，不保存全部窗口输出。

`cost.wall_seconds` 包括预测调用内的读取、推理、时间轴还原和结果列表构造，不包括外部模型加载、PTS 扫描或 JSON 写盘。`read_seconds` 是后台读取、预处理和锁页内存准备的累计时间；`forward_seconds` 包含输入上传、模型计算和 logits 回传。两者存在重叠，不能相加当作墙钟耗时。命令行额外打印 `command_elapsed_seconds`，包含从本次命令启动到该视频写盘完成的实际时间；批量模式下它是累计值。

## 批量推理

```bash
tennis-contact predict \
  --dataset data/dataset.json \
  --split validation \
  --checkpoint weights/best.pt \
  --device cuda \
  --output runs/validation-predictions
```

输出目录按数据清单中的ID组织：

```text
runs/validation-predictions/
├── match_001.json
├── match_002.json
└── ...
```

每个文件包含完整原生帧分数及 `sample_id`。`evaluate` 读取这一目录，并检查预测ID和PTS是否与数据清单一致；单视频模式产生的JSON不直接用作批量评价输入。

## 阈值配置

`--profile primary` 是默认配置，`--profile secondary` 读取权重中的另一组阈值。随仓库提供的推理权重配置为：

| profile | hit | bounce |
| --- | ---: | ---: |
| `primary` | 0.60 | 0.48 |
| `secondary` | 0.67 | 0.57 |

使用评价文件中的阈值时：

```bash
tennis-contact predict \
  --video data/video/match.mp4 \
  --checkpoint weights/best.pt \
  --thresholds runs/validation.json \
  --device cuda \
  --output runs/match.json
```

`--thresholds` 文件须包含顶层 `thresholds` 对象；它优先于 `--profile`。阈值只影响事件解码，不改变输出中的密集分数，因此可以用同一份批量预测文件评价不同工作点。

## 固定阈值评价

```bash
tennis-contact evaluate \
  --dataset data/dataset.json \
  --split validation \
  --predictions runs/validation-predictions \
  --hit-threshold 0.60 \
  --bounce-threshold 0.48 \
  --output runs/validation-fixed.json
```

评价总是从 `scores` 重新解码。`evaluate` 的阈值由它自己的参数决定，不自动使用预测JSON中的阈值或 `events`。

### 解码与匹配

1. 对 hit 和 bounce 分别提取局部峰，平顶峰取最左位置。
2. 保留达到对应阈值的峰，按分数从高到低执行半径5原生帧的NMS，同分优先较早帧。
3. 预测与同视频、同类别标注在 **±5原生帧**内进行一对一匹配，先最大化TP，再最小化匹配总误差。

容差按视频原生帧号计算，不按逻辑30Hz采样槽计算。不同帧率的视频中，5帧对应的物理时间长度可以不同。

### 评价报告

| 字段 | 含义 |
| --- | --- |
| `overall` | 所有来源与类别合并的事件计数和指标 |
| `by_type` | hit / bounce 分别统计 |
| `by_source` | 按数据清单 `source` 统计，并保留类别明细 |
| `thresholds` | 评价使用的两类阈值 |
| `split` | 本次评价的数据划分 |
| `threshold_origin` | `fixed` 或 `validation_search` |

每组指标包含TP、FP、FN、Precision、Recall、F1、平均匹配帧误差和每分钟未匹配预测数。

$$
P=\frac{TP}{TP+FP},\quad R=\frac{TP}{TP+FN},\quad
F_1=\frac{2TP}{2TP+FP+FN}.
$$

FP表示未匹配标注的预测，FN表示未匹配预测的标注。总体F1由合并后的计数计算，数据量较大的来源会影响总体结果，应同时查看分来源报告。

## 在validation选择阈值

```bash
tennis-contact evaluate \
  --dataset data/dataset.json \
  --split validation \
  --predictions runs/validation-predictions \
  --tune \
  --output runs/validation.json
```

搜索范围为0.01到1.01，步长0.01。1.01可以表示不输出该类事件。搜索以总体事件F1为主，同F1时优先较少FP，再优先较高阈值。

## 在holdout报告结果

先对holdout生成预测，并应用validation选出的阈值：

```bash
tennis-contact predict \
  --dataset data/dataset.json \
  --split holdout \
  --checkpoint weights/best.pt \
  --thresholds runs/validation.json \
  --device cuda \
  --output runs/holdout-predictions
```

再将同一组阈值传给评价命令：

```bash
HIT_THRESHOLD=$(python -c 'import json; print(json.load(open("runs/validation.json"))["thresholds"]["hit"])')
BOUNCE_THRESHOLD=$(python -c 'import json; print(json.load(open("runs/validation.json"))["thresholds"]["bounce"])')

tennis-contact evaluate \
  --dataset data/dataset.json \
  --split holdout \
  --predictions runs/holdout-predictions \
  --hit-threshold "$HIT_THRESHOLD" \
  --bounce-threshold "$BOUNCE_THRESHOLD" \
  --output runs/holdout.json
```

holdout只用于报告冻结工作点下的结果。`evaluate --tune` 用于其他split时会报错。
