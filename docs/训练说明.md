# 训练说明

TennisContactNet 直接从视频读取 RGB 帧，训练 `hit`（击球）与 `bounce`（落地）事件。训练所需数据格式见[数据格式](数据格式.md)，项目概览见 [README](../README.md)。

## 环境与权重

在项目根目录创建并激活 Conda 环境：

```bash
conda env create -f environment.yml
conda activate tennis-contact
```

模型不会联网下载参数，训练和推理都从本地权重读取：

| 文件 | 用途 |
| --- | --- |
| `weights/best.pt` | 默认推理权重；也可作为 `train --checkpoint` 的微调起点 |
| `weights/initialization.pt` | 默认训练初始化权重 |

两份权重使用相同的 TennisContactNet 结构。`--checkpoint` 只用于开始一次新训练；恢复训练应使用 `--resume` 指向 `training.pt`。

## 开始训练

以下命令使用清单中 `train` split 的全部视频。首次训练必须选择一个不含 `last.pt` 或 `training.pt` 的新输出目录：

```bash
tennis-contact train \
  --dataset data/dataset.json \
  --checkpoint weights/initialization.pt \
  --output runs/contact-v1 \
  --device cuda \
  --epochs 1 \
  --batch-size 4 \
  --lr 0.000001 \
  --scope backbone2 \
  --precision bf16 \
  --seed 20261028
```

默认训练顺序是清单中的视频顺序，以及每个视频内起点为 `0, 100, 200, ...` 的窗口顺序。每个窗口包含 100 个逻辑 30 Hz 核心位置及前后最多各 28 个上下文位置；采样依据视频的真实 PTS。

### 训练范围

| `--scope` | 可训练参数 | 适用场景 |
| --- | ---: | --- |
| `backbone2` | 73,248 | 默认；仅训练 `trunk.2.*` |
| `all` | 6,797,590 | 微调整个模型 |

两种范围下，`BatchNorm3d` 的运行统计都保持冻结；Dropout 在训练时启用。

### 优化与损失

- 优化器为 AdamW，`weight_decay=0.01`，无学习率调度器；梯度范数上限为 1.0。
- `--batch-size` 表示一次参数更新累计多少个视频窗口。窗口逐个前向和反向，不会同时把整个批次的 RGB 张量放入显存；末批不足指定数量时仍会更新。
- eventness 目标是按事件时间距离生成的软高斯目标，`sigma=0.04` 秒。eventness 使用带正样本权重的 BCE，权重由当前 `train` split 的背景质量与软事件质量计算。
- 类型项使用 `sigmoid(eventness) * softmax(type)` 得到的 `hit`、`bounce` 联合概率做 BCE。它只监督距离最近事件不超过 0.08 秒且类别不歧义的位置，系数为 0.5，固定归一分母为 `36.39117789626757`。
- `--precision bf16` 只对视觉骨干启用 BF16；局部状态、GRU、输出头和损失保持 FP32。`--precision fp32` 关闭混合精度。

## 输出文件

训练会在每 64 次更新、收到安全中断信号后以及本次运行结束时保存：

| 文件 | 内容 | 使用方式 |
| --- | --- | --- |
| `last.pt` | 模型状态和阈值元数据 | 传给 `predict --checkpoint`，也可作为下一次新训练的 `--checkpoint` |
| `training.pt` | 模型、AdamW、游标、请求顺序、随机数状态、训练配置和累计成本 | 只用于 `train --resume` |

命令结束时输出 JSON。主要字段含义如下：

| 字段 | 含义 |
| --- | --- |
| `status` | `complete` 表示全部请求完成；`paused` 表示达到 `max-steps`；`interrupted` 表示收到 SIGINT 或 SIGTERM |
| `steps` | 从训练开始累计完成的参数更新数 |
| `cursor` / `requests` | 已消费请求数 / 总请求数；完整结束时两者相等 |
| `updates_this_run` | 本次进程完成的参数更新数 |
| `wall_seconds` | 本次进程的总墙钟时间 |
| `video_read_seconds` | 本次进程读取和传输视频帧的时间 |
| `forward_backward_seconds` | 本次进程前向、反向和优化器更新的时间 |
| `peak_allocated_bytes` | 本次进程的 CUDA 峰值已分配显存；CPU 训练时为 0 |

`training.pt` 内的 `cost` 会跨恢复累计 `wall_seconds`、`video_read_seconds`、`forward_backward_seconds` 和 `updates`。读取在后台与模型计算重叠；总墙钟时间还包含数据准备和保存，因此不等于两个分项之和。CUDA 计算与传输分项使用设备事件计时，不再为了每个窗口的计时强制同步设备。

每视频的采样映射和原生帧目标只构造一次，类别平衡只统计单个 epoch 的窗口；恢复时在完整训练配置和请求顺序一致的前提下复用已保存的类别平衡。视频读取使用有界帧缓存和单窗口预取，保持显式请求顺序及镜像操作。梯度累积不需要把整批 RGB 同时加载到内存。结束或中断恰逢定期保存时，只写一次最终 checkpoint。

## 暂停与恢复

`--max-steps` 是从训练开始累计计算的参数更新上限。数据请求足够时，下面的命令先在累计 100 步暂停，再从同一目录恢复到累计 200 步；若全部请求先完成，状态会是 `complete`：

```bash
tennis-contact train \
  --dataset data/dataset.json \
  --checkpoint weights/initialization.pt \
  --output runs/contact-resumable \
  --device cuda \
  --epochs 1 \
  --batch-size 4 \
  --lr 0.000001 \
  --scope backbone2 \
  --precision bf16 \
  --seed 20261028 \
  --max-steps 100

tennis-contact train \
  --dataset data/dataset.json \
  --checkpoint weights/initialization.pt \
  --output runs/contact-resumable \
  --resume runs/contact-resumable/training.pt \
  --device cuda \
  --epochs 1 \
  --batch-size 4 \
  --lr 0.000001 \
  --scope backbone2 \
  --precision bf16 \
  --seed 20261028 \
  --max-steps 200
```

首次命令使用新的 `runs/contact-resumable` 目录；恢复命令继续写同一目录。恢复时必须保持 `--dataset` 路径及内容、训练顺序文件的路径及内容、`epochs`、`batch-size`、`lr`、`scope`、`precision`、`seed` 和 `device` 一致。修改 `epochs` 会改变请求总序列并导致恢复配置校验失败。`max-steps` 不属于恢复配置，可以提高；如果上限不高于断点中的累计 `steps`，本次不会执行新更新。

收到 SIGINT 或 SIGTERM 后，训练会完成当前批次的反向与参数更新，在批边界写入 `last.pt` 和 `training.pt`，然后以 `interrupted` 状态结束。

## 可选预设

`docs/video-splits.json` 和 `docs/training-order.json` 是可选预设，自有数据训练无需使用：

- `video-splits.json` 提供一组视频 ID 的 split 配置。`prepare` 不会自动读取它；只有数据中的视频 ID 与该文件匹配时，才应据此填写 `dataset-input.json` 的 `split`。
- `training-order.json` 可通过 `--order docs/training-order.json` 指定窗口顺序和水平翻转。它要求 `train` 视频 ID 集合完全匹配，并且每个数据窗口恰好出现一次；文件中的正样本权重也必须与当前数据重新计算的值一致。

只匹配部分视频 ID、视频时长不同或窗口集合不同的数据不能使用这些预设。
