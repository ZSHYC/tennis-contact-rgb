# 训练、恢复与复现边界

以下命令均在项目根目录及 `conda activate tennis-contact` 后运行；环境创建方式见根目录README。

## 两份权重

- `weights/best.pt`：最佳 EO 最终权重，独立项目中称为 TennisContactNet。
- `weights/initialization.pt`：EO 续训之前的成熟 RGB 父模型 O，用于复现最后阶段或开始新数据适配。

两者均为同一网络结构，6,797,590 参数，583 个状态张量。文件不含原研究目录的动态加载器、缓存路径或文件指纹。默认构造网络不联网下载权重。

## 输入与监督

视频按整数 PTS 与 time_base 获得真实时间，映射到逻辑30Hz。一个窗口输出100个核心槽，前后最多各28个上下文槽，首尾不填充无效帧。最近邻距离相等时选择较早的原生帧；重复采样的原生帧保留在时序输入中，监督权重除以其完整逻辑轴上的重复次数。

监督使用被选中原生帧的真实 PTS，不使用理想采样时刻冒充观测时间。事件软目标为距最近事件时间的高斯，σ=0.04秒；类型监督限于最近事件距离≤0.08秒的范围，击球/落地等距歧义不参与类型项。

训练目标包含两部分，event项除以当前批核心权重质量，type项沿用历史固定归一分母36.39117789626757：

1. eventness 的加权 BCEWithLogits，正权重由 TRAIN 的背景/软事件质量计算。
2. `sigmoid(eventness) × softmax(type)` 联合分数的双类 BCE，以经过正权重校正的软事件目标监督正确类别；类型项系数0.5。

它不是将 soft eventness 改成硬标签，也不是简单替换成类型交叉熵。背景来自完整视频时间轴，不额外生成轨迹负样本。

## 两种训练范围

`--scope backbone2` 仅训练 `trunk.2.*`，共73,248参数。这对应最佳 EO 的最后一轮事件续训范围。`--scope all` 开放全部参数，便于继续研究和适配新数据；它不会自动获得历史 EO 成绩。

AdamW 的 weight_decay=0.01，梯度裁剪范数1.0，无 scheduler。默认 lr=1e-6、batch-size=4、seed=20261028。每个窗口依次反传累积后更新，显存不随四个完整窗口同时堆叠；不满一批仍正常提交。BatchNorm 统计冻结，Dropout 训练时启用。

BF16 模式只包围 X3D 视觉计算。局部状态、GRU、最终 logits 和损失为 FP32；正式预测固定走完整 FP32。两种精度不宣称逐值等价。

## 使用自己的数据

默认按数据清单中的 TRAIN 视频顺序，再按每视频核心起点0、100、200…依次训练。`epochs` 重复这一固定顺序；validation/holdout 不参与梯度或正权重估计。

```bash
tennis-contact train --dataset data/dataset.json \
  --checkpoint weights/initialization.pt --output runs/train \
  --device cuda --batch-size 4 --epochs 1 --scope backbone2
```

每64步、安全中断的批边界和终点保存：

- `runs/train/last.pt`：独立推理权重，可直接传给 `predict --checkpoint`。
- `runs/train/training.pt`：训练恢复断点，保留模型、Adam、游标、请求顺序、四类 RNG、数据内容与训练设置，以及累计成本。

```bash
tennis-contact train --dataset data/dataset.json \
  --output runs/train --resume runs/train/training.pt \
  --device cuda --batch-size 4 --epochs 1 --scope backbone2
```

恢复时使用原来的数据清单、epochs、batch-size、lr、scope、precision、seed 和请求顺序。标签或 PTS 改变时，按新的实验开始，避免把两个不同训练问题拼接在同一断点上。这里直接比较必要配置内容，没有文件哈希或指纹。

`--max-steps` 是累计更新上限，可先停在2步，恢复时改为4步。SIGINT/SIGTERM 会完成当前批并保存；未提交批不会被冒充为完成。

## 原最后阶段的固定配方

[video-splits.json](video-splits.json) 保留原1,584 TRAIN、505 validation视频ID。[training-order.json](training-order.json) 保留原8,250个训练请求的顺序、核心起点和水平翻转，共4,084个翻转请求；不包含原视频、标签、图像或缓存。

如果拥有并准备了相同的数据，可以运行：

```bash
tennis-contact train --dataset data/original-dataset.json \
  --checkpoint weights/initialization.pt --output runs/reproduction \
  --order docs/training-order.json --device cuda --epochs 1 \
  --batch-size 4 --lr 0.000001 --scope backbone2 --precision bf16 --seed 20261028
```

指定配方时核对 TRAIN 视频集合与请求范围，按原顺序和翻转执行；正权重采用原配方的14.330945259756955，并与当前数据重算值比较。原FP32目标的不同求和路径会产生约1e-8的权重差异，不把它解释为不同数据。

独立代码已做短窗口网络等价、真实原视频输入对齐和训练恢复验证；**未重新完成8,250请求训练或完整六来源评价**。历史结果还依赖父模型此前多轮训练、原始数据与标注、随机数消耗顺序和设备数值行为；提供最后阶段配方不等于保证跨机器训练后的权重逐bit一致。

## 成本与长任务

训练摘要记录本次与累计耗时、更新数及CUDA峰值显存；推理记录视频读取、前向和时间轴还原耗时。原视频直接读取的成本与旧缓存路径不同，不能引用旧吞吐冒充新项目的速度。

长训练可由使用者在 tmux 中运行上述命令；中断后从 `training.pt` 恢复。不要把“进程退出0”单独当作完整训练完成，须查看返回的 `status`、`cursor` 与总 `requests`。
