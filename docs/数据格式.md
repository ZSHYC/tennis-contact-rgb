# 数据格式

[返回 README](../README.md)

仓库不附带训练或评价数据。准备好视频与完整事件标注后，使用输入清单生成训练、推理和评价共同读取的 `data/dataset.json`。

## 推荐目录

```text
data/
├── dataset-input.json
├── video/
│   ├── match_001.mp4
│   ├── match_002.MOV
│   └── match_003.mov
└── GT/
    ├── match_001.csv
    └── match_003/
        ├── 000042.json
        └── 000077.json
```

`dataset-input.json` 必须逐条列出视频；`prepare` 不会自动扫描目录。`video` 和外部标注路径都相对于 `dataset-input.json` 所在目录解析。

## 输入清单

以下示例分别使用 CSV、内联事件和 LabelMe 目录：

```json
{
  "samples": [
    {
      "id": "match_001",
      "video": "video/match_001.mp4",
      "split": "train",
      "source": "local_court",
      "annotations": "GT/match_001.csv"
    },
    {
      "id": "match_002",
      "video": "video/match_002.MOV",
      "split": "validation",
      "source": "local_court",
      "events": [
        {"frame_number": 42, "event_type": "hit"},
        {"frame_number": 77, "event_type": "bounce"}
      ]
    },
    {
      "id": "match_003",
      "video": "video/match_003.mov",
      "split": "holdout",
      "source": "local_court",
      "annotations": {
        "path": "GT/match_003",
        "frame_numbering": "one_based"
      }
    }
  ]
}
```

每个 sample 的字段如下：

| 字段 | 必需 | 说明 |
| --- | --- | --- |
| `id` | 是 | 非空且全清单唯一；不能包含 `/` 或 `\` |
| `video` | 是 | 视频路径；扩展名仅支持大小写不敏感的 `.mp4`、`.mov` |
| `split` | 是 | `train`、`validation` 或 `holdout` |
| `source` | 否 | 数据来源名称；省略时为空字符串 |
| `events` | 二选一 | 内联事件数组，帧号始终从 0 开始 |
| `annotations` | 二选一 | CSV 路径、LabelMe 目录路径，或带帧号规则的路径对象 |

同一实际视频不能出现在不同 split。划分单位是完整视频，不要把同一视频的帧拆到训练集和验证集。每个视频都必须完整标注整个时间轴；不支持只标一段区间。确认整段视频没有 `hit` 或 `bounce` 时，使用 `"events": []` 明确表示全背景视频。

视频路径中不能包含名为 `visualization` 的目录，文件名也不能包含 `_visualized`。这些文件不会被作为模型输入。

## 帧号与标签

帧号默认从 0 开始。只有外部 CSV 或 LabelMe 目录需要使用从 1 开始的帧号时，才配置对象形式：

```json
{
  "annotations": {
    "path": "GT/match_001.csv",
    "frame_numbering": "one_based"
  }
}
```

`frame_numbering` 只能是 `zero_based` 或 `one_based`。内联 `events` 不接受该选项，始终使用零基帧号。

支持的标签及归一结果如下：

| 输入标签 | 归一结果 |
| --- | --- |
| `hit`、`near_hit`、`far_hit` | `hit` |
| `bounce`、`near_bounce`、`far_bounce` | `bounce` |
| `net`、`near_net`、`far_net` | 忽略 |

标签比较不区分大小写，并会去除首尾空白。其他标签会直接报错。归一后，同一帧不能同时是 `hit` 和 `bounce`，同一帧同一类别也不能重复。

### CSV

CSV 必须包含 `frame_number`，并包含 `event_type` 或 `label`。文件可使用 UTF-8 或带 BOM 的 UTF-8：

```csv
frame_number,event_type
42,hit
77,bounce
103,near_hit
```

### 内联事件

内联事件直接写在 sample 的 `events` 数组中：

```json
{
  "events": [
    {"frame_number": 42, "event_type": "hit"},
    {"frame_number": 77, "event_type": "bounce"}
  ]
}
```

也可以把 `event_type` 写成 `label`。

### LabelMe 目录

`annotations` 指向目录时，程序读取该目录下的 `*.json`。每个文件名必须以帧号开头，例如 `000042.json` 或 `42_contact.json`；帧号取文件名开头的连续数字。标签读取自每个文件的 `shapes[].label`。

## 生成 dataset.json

激活项目环境后，在项目根目录运行：

```bash
conda activate tennis-contact
tennis-contact prepare \
  --input data/dataset-input.json \
  --output data/dataset.json
```

`prepare` 会用 `ffprobe` 读取视频 packet 的整数 PTS 和视频 `time_base`，排除剪辑预滚中标为 discard 的包，再按显示时间排序，生成严格递增的真实时间数组。这一步只读取容器时间戳，不为取得时间轴而完整解码视频，也不使用帧号除以名义 FPS 估算时间。输出结构如下：

```json
{
  "schema": 1,
  "frame_numbering": "zero_based",
  "samples": [
    {
      "id": "match_001",
      "video": "video/match_001.mp4",
      "split": "train",
      "source": "local_court",
      "events": [
        {"frame_number": 1, "event_type": "hit"}
      ],
      "frame_times": [0.0, 0.03336666666666667, 0.06673333333333334]
    }
  ]
}
```

| 输出字段 | 说明 |
| --- | --- |
| `schema` | 当前格式版本，值为 1 |
| `frame_numbering` | 输出统一为 `zero_based` |
| `video` | 相对于输出 `dataset.json` 所在目录的路径 |
| `events` | 已归一并按帧号、类别排序的 `hit` / `bounce` 事件 |
| `frame_times` | `prepare` 从视频真实 PTS 生成的逐帧秒数 |

后续的 `train`、`predict --dataset` 和 `evaluate` 读取这份输出。不要手工填写或改写 `frame_times`；视频改变后应重新运行 `prepare`。

## 常见错误

| 错误信息或现象 | 检查位置 |
| --- | --- |
| `FileNotFoundError` | 从 `dataset-input.json` 所在目录出发检查 `video` 的相对路径和大小写 |
| `unsupported video extension` | 输入只支持 `.mp4`、`.mov`；扩展名可大小写混用 |
| `visualized video is not model input` | 改用原视频，排除 `visualization` 目录和名称含 `_visualized` 的文件 |
| `ffprobe failed` | 确认已激活 Conda 环境，文件可由 FFmpeg 解码且包含视频流 |
| `video PTS must be finite and strictly increasing` | 用 `ffprobe` 检查视频逐帧时间戳；重新封装或修复时间戳后再准备 |
| `unsupported annotations` | 检查 `annotations` 路径是否存在；文件应是 CSV，LabelMe JSON 直接放在所指定的目录下 |
| `annotation CSV needs frame_number and event_type/label` | 检查 CSV 表头拼写 |
| `LabelMe filename must start with a frame number` | 将 JSON 文件名改为以对应帧号开头 |
| `unsupported event label` | 将标签改为上表支持的名称；`net` 类会被忽略 |
| `duplicate normalized event` | 删除同一帧归一到同一类别的重复标注 |
| `a frame cannot be both hit and bounce` | 检查报错帧的两个事件，只保留正确类别 |
| `event frame exceeds video` | 检查零基/一基设置，并确认标注对应当前视频版本 |
| `missing or duplicate sample id` | 检查 `id` 是否非空、唯一且不含路径分隔符 |
| `needs split train/validation/holdout` | 为 sample 填写三个允许值之一 |
| `video appears in multiple splits` | 让同一实际视频只属于一个 split |
| `invalid frame_times` | 不要手工编辑 `dataset.json`；从输入清单重新运行 `prepare` |

训练参数和断点恢复方式见[训练说明](训练说明.md)。
